# なぜコンテナか

## このレッスンでわかること

- 「自分のマシンでは動く」が、何が揃っていないと起きるか
- コンテナは軽量 VM ではなく、ホストのカーネルを共有した隔離プロセスであること
- イメージ（雛形）とコンテナ（実行中）の違い

## 前提

- [トラック概要](./README.md)

## 本文

サーバーが動かない理由の多くはコードではなく環境である。

- Node の版が違う
- `go` が入っていない
- ポート 3000 が既に使われている
- 環境変数 `DATABASE_URL` がない
- OS の共有ライブラリが違う

コンテナは、「アプリが仮定しているファイルシステムと環境変数と起動コマンド」をまとめて持ち歩く。別のマシンでは Docker（または互換ランタイム）があれば、同じイメージから同じ形で起こせる、というのが約束である。完全な同一までは保証しないが、生の「手元の PATH に何が入っているか」よりずっと狭い。

### VM との違い（導入レベル）

仮想マシンはゲスト OS ごと持つ。コンテナはホスト Linux のカーネルを共有し、名前空間と cgroup で「見え方と資源」を分ける。だから起動が速く、イメージも VM より小さいことが多い。Windows や macOS 上の Docker は、実際には Linux VM の中でコンテナを走らせている、という二重構造がある。導入では「コンテナの中は Linux プロセス」と思ってよい。

### イメージとコンテナ

- **イメージ** — 読み取り専用の雛形。層が積み上がったスナップショット。`hono-app:dev` のような名前
- **コンテナ** — その雛形から起こした実行中（または停止中）のインスタンス。同じイメージから何個でも

料理のレシピの写真がイメージ、今夜の皿がコンテナ、に近い。皿を捨ててもレシピは残る。データを皿だけに書くと、捨てたときに消える（ボリュームは予定レッスン）。

### このリポジトリの他トラックとの接点

- Hono / Go のサーバーは、コンテナ内で `Listen` するプロセスになる
- `-p 3000:3000` はホストの TCP 3000 を、コンテナの 3000 へ繋ぐ
- `127.0.0.1` は「そのネットワーク名前空間の自分」なので、ホストブラウザから見るには公開が必要

## 確認

- 同じイメージからコンテナを二つ起動できるか
- コンテナを消したら、イメージも消えるか（通常）
- 「軽量 VM」と呼ばない理由を、カーネルの言葉で一言
